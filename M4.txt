//Regular expressions 
a formal language for specifying text strings 

Word characters (\w) → [a-zA-Z0-9_]
Non-word characters (\W) → anything not in [a-zA-Z0-9_], including:
   Spaces
   Punctuation (. , ; ! ? : - " ')
   Symbols (@ # $ % & *)


| Symbol  | Meaning                          | Example                                |       |                          |
| ------- | -------------------------------- | -------------------------------------- | ----- | ------------------------ |
| `.`     | Any one character                | `a.c` matches `abc`, `axc`             |       |                          |
| `^`     | Start of string                  | `^a` matches `apple`                   |       |                          |
| `$`     | End of string                    | `e$` matches `apple`, `pie`            |       |                          |
| `*`     | 0 or more times                  | `lo*` matches `l`, `lo`, `loo`         |       |                          |
| `+`     | 1 or more times                  | `lo+` matches `lo`, `loo`, but not `l` |       |                          |
| `?`     | 0 or 1 time (optional)           | `colou?r` matches `color` and `colour` |       |                          |
| `[]`    | Any one character from set       | `[aeiou]` matches vowels               |       |                          |
| `[^]`   | Any one character **not** in set | `[^0-9]` matches non-digit             |       |                          |
| `{n}`   | Exactly n times                  | `a{3}` matches `aaa`                   |       |                          |
| `{n,}`  | n or more times                  | `a{2,}` matches `aa`, `aaa`...         |       |                          |
| `{n,m}` | Between n and m times            | `a{2,4}` matches `aa`, `aaa`, `aaaa`   |       |                          |
| \`      | \`                               | OR                                     | \`cat | dog`matches`cat`or`dog\` |
| `()`    | Grouping                         | `(ab)+` matches `ab`, `abab`, `ababab` |       |                          |

| `\s`    | Whitespace         | space, tab, newline |
| `\S`    | Non-whitespace     | a, b, 1, etc.       |

//problems with tokenization 
 when we break text into tokens - tokenization - we run into ambigous cases 
  1. punctuation marks 
  2. capitalization 
  3. multi-word expressions(san francisco)
  4. contractions (I'm,isn't)

  ex: 
  Input: "I’m going to San Francisco at 100 m.p.h."
  Expected tokens: ["I", "am", "going", "to", "San Francisco", "at", "100", "mph"]
  actual tokens:  ["I", "’", "m", "going", "to", "San", "Francisco", "at", "100", "m", ".", "p", ".", "h", "."]

   so to solve these use tokenization techniques 
   | **Technique**                      | **What it does**                                                                                                   |
    | ---------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
    | **Contraction expansion**          | `isn’t` → `is` + `not`, `I’m` → `I` + `am` using rules or dictionaries                                             |
    | **Hyphen handling**                | Keeps or splits hyphenated phrases depending on context (e.g., `"state-of-the-art"` can be one token)              |
    | **Lowercasing**                    | Converts all text to lowercase to treat `The` and `the` the same                                                   |
    | **NER (Named Entity Recognition)** | Groups tokens like `"San Francisco"` or `"New York"` into a single entity                                          |
    | **Abbreviation detection**         | Preserves abbreviations like `Ph.D.`, `m.p.h.` using custom rules                                                  |
    | **Advanced tokenizers**            | Use tools like **spaCy**, **BERT tokenizer**, or **nltk Treebank tokenizer** which handle most of these cases well |

 different lanaguages have unique challenges in tokenization 
  english -> contraction,punctuation,possesives,hyphenated words 
  chinese -> no space between words 
  social media -> emojis 
 
  techniques 
  rule based tokenization - use language specific rules 
  dictionary/lexicon-based - matchs words against a vocabulary 
  preprocessing - lowercasing,punctuation removal,emoji normalization,contraction expansion 

  use language specific tokenizers (hugging face,mecab,spacy)

//lemmatization 
 Lemmatization is the process of reducing inflected or variant forms of a word to its base or dictionary form, called the lemma.
   are,am is -> be 
   car's,cars -> car 
   running -> run 

   uses 
   information retrieval 
   machine translation 
   text normalisation 

    | Aspect                        | Notes                                                                                                                                      |
    | ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
    | **Stemming vs Lemmatization** | Stemming just removes suffixes (`cars` → `car`, `better` → `better`), lemmatization is dictionary-based and POS-aware (`better` → `good`). |
    | **Applications**              | IR, MT, text preprocessing, sentiment analysis, information extraction                                                                     |
    | **Requirement**               | Part-of-speech tagging + lexicon/dictionary for accurate results                                                                           |

  Lemmatization reduces words to their canonical form, making NLP models more efficient and semantically consistent, unlike simple stemming which may produce non-words.

//morphology 
 morphemes : small meaningful units that make up words 
   Morphology is the study of the internal structure of words and how they are formed from smaller meaningful units called morphemes.

   It helps NLP systems understand word meaning, formation, and grammatical relationships.
   stem vs affix 
    | Type            | Definition                                         | Examples                                                                   |
    | --------------- | -------------------------------------------------- | -------------------------------------------------------------------------- |
    | **Stem / Root** | The core meaning-bearing unit of a word            | `book` (in `books`), `run` (in `running`)                                  |
    | **Affix**       | A morpheme attached to a stem, usually grammatical | Prefixes: `un-` (`unhappy`) <br> Suffixes: `-ed` (`walked`), `-s` (`cats`) |

   words = stems + affixes 

   uses 
    text normalization - (running -> run)
    infromation retrieval - (match cat and cats )
    machien translation 
    parts of speech tagging 

//stemming 
  Stemming is the process of reducing words to their base or root form, called the stem, by crude removal of affixes.
   
   Unlike lemmatization, stemming does not consider the dictionary form or part of speech; it simply chops off endings.
   ex: automatic/automates/automation -> atuomat 
   used in 
   information retrieval -> treat different forms of a word as equivalent 

stemming vs lemmatization 

    | Aspect   | Stemming                           | Lemmatization                      |
    | -------- | ---------------------------------- | ---------------------------------- |
    | Method   | Crude chopping of affixes          | Dictionary + POS-aware             |
    | Output   | May not be a real word (`automat`) | Always a valid lemma (`be`, `run`) |
    | Accuracy | Less precise                       | More precise                       |
    | Speed    | Faster                             | Slower (needs dictionary lookup)   |
